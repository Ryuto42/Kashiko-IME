# kashiko-im

macOS Swift フロントエンドから使われる日本語IMEエンジン。ローマ字→ひらがな変換、GPT-2ベースのニューラルかな漢字変換、学習キャッシュ、システム辞書を提供します。

フロントエンドのインストール手順:
- macOS: [kashiko-macos](../kashiko-macos/README.md)

## Features

- ニューラルかな漢字変換（llama.cppによるGGUF推論）
- 変換学習（ユーザーの変換履歴を記憶し、完全一致・前方一致で候補を優先表示）
- 日本語・英数字の混合入力（Shift切り替え）
- 前後の文脈を考慮した変換（同音語を直前の文で判別。文脈を読めないアプリでは自前の確定履歴で代替）
- システム辞書・ユーザー辞書による候補補完
- タイプミスの補正候補（キーボード配置を考慮した打鍵誤りの推定。変換応答後もバックグラウンドで探索を継続）
- ローマ字変換で崩れた英単語の復元（確度に応じて候補順位を決定）
- 言語モデルの尤度による候補の並べ替えと品質ゲート（同音の紛れを除外し、表示数を品質で決定）
- ライブ変換の自己評価と条件付き再生成（不自然な結果のみビーム探索で作り直し）

> [!NOTE]
> モデル推論だけでは語彙が限られるため、システム辞書の併用を強く推奨します。システム辞書はIMEに同梱されていないため、別途インストールが必要です。詳しくは [Dictionary](#dictionary) を参照してください。

## Key Bindings

### ひらがな入力モード

| キー | 動作 |
|------|------|
| 文字キー | ローマ字入力 → ひらがな変換 |
| Space / Tab / ↓ | かな漢字変換を開始 |
| Enter | ひらがなのまま確定 |
| Escape | 入力をキャンセル |
| Backspace | 1文字削除 |
| Delete | カーソル位置の文字を削除 |
| ← → | カーソル移動 |
| Home / End | カーソルを先頭 / 末尾に移動 |
| Ctrl+K | カタカナモードに切り替え |
| Ctrl+Space | 全角スペースを入力 |

### 変換モード

| キー | 動作 |
|------|------|
| Space / Tab / ↓ | 次の候補 |
| ↑ | 前の候補 |
| ← → | 変換対象の文節を単語単位で左右に移動 |
| Shift+← → | 変換対象の文節を単語単位で伸縮（区切りがずれた場合） |
| 1-9 | 候補を番号で選択・確定 |
| Enter | 選択中の候補を確定 |
| Escape | 変換をキャンセル（ひらがなに戻る） |
| 文字キー | 選択中の候補を確定して新しい入力を開始 |

確定した直後に `Ctrl+Backspace` を押すと、確定を取り消して変換モードに戻せます（標準のCocoaテキスト部品で動作。一部のElectron系アプリでは効かない場合があります）。

### モード切り替え

| キー | 動作 |
|------|------|
| Shift+英字 | 英数字モードに切り替え + 大文字入力 |
| Ctrl+K | カタカナモードに切り替え |
| Right Super | 英数字/カタカナ → ひらがなモードに復帰 |
| Ctrl+Shift+L | ライブ変換のON/OFF |

### 英数字モード

英数字モードでは文字がローマ字変換されず、そのまま入力されます。日本語と英語を混ぜて入力し、Spaceで変換するとひらがな部分のみ変換されます。

例: `わたしはLinuxが` → 変換 → `私はLinuxが`

## Configuration

設定ファイル: `~/Library/Application Support/com.kashiko.kashiko-im/config.toml`

```toml
[conversion]
live_conversion = true          # ライブ変換を起動時に有効化（Ctrl+Shift+L で実行中も切替。既定ON）
composing_chunk_len = 30        # ライブ変換で1回のモデル変換が扱う読みの最大文字数（= 1キーあたりレイテンシの上限）
strategy = "adaptive"           # 変換ストラテジー（adaptive / light / main）
num_candidates = 9              # 変換候補数（Space押下時）
n_threads = 4                   # 推論スレッド数（0 = 全コア使用）
model = "jinen-v1-small-q5"     # メインモデル（モデルID or GGUFパス）
light_model = "jinen-v1-xsmall-q5"  # 軽量モデル（ビームサーチ・長文用）
use_context = true              # Surrounding Textを変換に使用する
max_context_length = 32         # 変換に渡す前方文脈の最大文字数（前の一文が入る長さ）
short_input_threshold = 10      # ビームサーチを使うトークン数の上限
beam_width = 3                  # ビーム幅
max_latency_ms = 100            # メインモデルの許容レイテンシ（ms）。超過時は軽量モデルに自動切替（0 = 無効）
dict_path = "/path/to/dict.bin" # システム辞書パス（省略時はデータディレクトリの dict.bin。[Dictionary](#dictionary) 参照）

[learning]
enabled = true                 # 変換学習の有効/無効
max_entries = 10000            # 学習エントリの最大数
```

> [!NOTE]
> 上記は主要な設定項目の抜粋です。全項目の正確な既定値と説明は [`config/default.toml`](config/default.toml) を参照してください（各設定行に日本語コメント付き）。

### Live Conversion

入力と同時にかな漢字変換の結果をプリエディットへリアルタイム表示します（Spaceを押さずに変換が進む）。`Ctrl+Shift+L` でON/OFFを切り替えられ、既定では `live_conversion = true` で有効です。

長文入力でも1キーあたりのレイテンシを一定に保つため、変換中のバッファを内部で最大 `composing_chunk_len` 文字（既定30）のチャンクに分割し、編集した箇所のチャンクだけを再変換します。チャンクは内部的な分割で、ユーザーには連続した1つのプリエディットとして見えます。記号・数字の連続は日本語とは別チャンクに分けてそのまま通すため、`123456` のような並びが変換で崩れることはありません。

ライブ変換は1候補のgreedyデコードで行いますが、greedyは各ステップで最善手に飛びつくため近視眼的で、ビーム探索なら避けられる不自然な文に入り込むことがあります。そこで**自己評価による条件付き再生成**を行います:

1. greedyで変換する（従来どおり）
2. 生成時に得た対数確率から文字単位NLLを求める。**サンプリング直前のlogitsを読むだけなので追加の推論コストはゼロ**です
3. 閾値（既定1.5）以下ならそのまま採用 — 通常ケースは従来と同じコスト
4. 超えた（不自然な）ときのみ、ビーム3本で再生成して最良を採用

毎キーストロークでビームを回すのは現実的でないため、「悪いと判定したときだけ」払う設計になっています。

学習キャッシュもライブ変換に反映されますが、**モデルを飛ばして即返すことはしません**。学習形とモデルの出力が食い違ったときだけ両者を文脈込みでスコアリングし、学習側に優遇（0.15）を与えて選びます。両者が一致する通常ケースでは追加コストは発生しません。

### Context-aware Conversion

同音語の選択は直前の文に依存します。カーソル左側の確定済みテキストを変換プロンプトの文脈スロットに渡すことで、この判別を行います。

- 文脈の長さは `max_context_length`（既定32文字）で決まります。**前の一文が収まる長さが必要**で、短すぎると同音語の判別に必要な手がかりが切り落とされます。長くすると毎回のプロンプトが伸びるため、レイテンシとのトレードオフになります。
- 文脈の取得は macOS の `string(from:)` に依存しますが、**Electron系エディタやターミナルなど実装していないアプリが多く**、そこでは文脈が空で届きます。その場合は**このIME自身が直近に確定したテキスト**を文脈として代用します（カーソル左にあるのは同じ文字列なので成立します）。アプリが文脈を返せる場合は常にそちらを優先します。
- 代用文脈はフォーカス移動（`reset`）で破棄します。別のアプリ・別の位置では直前の確定内容が文脈として成立しないためです。

### Conversion Strategy

`strategy` で変換時のモデル使い分けを制御できます。

| 値 | 説明 | 読み込むモデル |
|---|---|---|
| `adaptive` | デフォルト。レイテンシに応じてメイン・軽量モデルを動的に切り替え | メイン + 軽量 |
| `light` | 軽量モデルのみ使用。メモリ消費が少なく、低スペックPCにおすすめ | 軽量のみ |
| `main` | メインモデルのみ使用（ビームサーチなし） | メインのみ |

低スペックのPC（メモリが少ない、CPUが遅い等）では `strategy = "light"` を設定すると、軽量モデル1つだけで動作するためメモリ使用量が削減され、レスポンスも安定します。

```toml
[conversion]
strategy = "light"
```

### Performance Tuning

CPU高負荷時（Rustビルド中など）にかな漢字変換が遅くなる場合は、`n_threads` を小さくするとレスポンスが改善します。

### Dictionary

辞書の構築・管理については [kashiko-cli の README](../kashiko-cli/README.md) を参照してください。

#### System Dictionary

double-array trieベースのシステム辞書で、モデル推論に加えて辞書からの変換候補を提供します。

- デフォルトパス: `~/Library/Application Support/com.kashiko.kashiko-im/dict.bin`
- `dict_path` で任意のパスを指定可能
- ファイルが存在しない場合は辞書なしで動作

`make install` が自動でダウンロードしますが、手動で配置する場合は以下のとおりです:

```bash
curl -LO https://github.com/togatoga/kashiko/releases/download/v0.1.0/dict.tgz
tar xzf dict.tgz
mkdir -p ~/Library/"Application Support"/com.kashiko.kashiko-im
cp dict.bin ~/Library/"Application Support"/com.kashiko.kashiko-im/
```

自分でビルドする場合は [kashiko-cli の README](../kashiko-cli/README.md) を参照してください。

#### User Dictionary

ユーザー辞書ディレクトリにファイルを配置すると、ユーザー辞書として読み込まれます。

- デフォルトパス: `~/Library/Application Support/com.kashiko.kashiko-im/user_dicts/`
- ディレクトリ内のファイルはすべて自動で読み込み（KRKNバイナリ・Mozc TSV を自動判定）
- ディレクトリが存在しない場合はユーザー辞書なしで動作

変換候補の優先順位:

1. 📝 学習キャッシュ
2. 👤 ユーザー辞書
3. 🤖 モデル推論 ＋ 📚 システム辞書（尤度で並べ替え・選別。下記参照）
4. 🔄 Rewriter（英字全角半角・記号バリアント）
5. ひらがな / カタカナ（常に最下部）

半角カタカナは候補に表示しません（全角形と並ぶとノイズになるため）。

#### 候補の品質ゲート

モデルと辞書の候補は、確定前に言語モデルで文字単位の尤度（NLL）を評価し、**並べ替えと選別**を行います。ビーム順はデコーダ自身の経路確率にすぎず、同音の紛れ（`パケットの役割と…` の隣に並ぶ `パケットの約割と…`）を上位に残してしまうためです。

- 表示する候補数は**固定ではなく品質で決まります**。最良候補から一定のマージン（文字単位NLLで既定0.55）を超えて劣る候補は、順位を下げるのではなく**候補から除外**します。マージンを相対値にしているのは、文の難易度に自動追従させるためです。
- 逆に**すべてが高評価なら全件を残します**（固定数に切り詰めません）。
- 絶対上限（既定1.6）も併用し、最良候補すら悪い場合に「最良に近いから」で通ることを防ぎます。
- モデルが迷っている場合でも**最低2件は必ず残す**ため、候補が空になることはありません。
- 学習・ユーザー辞書の候補は選別対象外で最上位を維持します（ユーザー自身の選択がモデルの評価に勝ちます）。ひらがな・カタカナも常に最下部に残ります。
- 読みが短い場合（既定3文字未満）は候補が少なく既に十分なため、評価をスキップしてレイテンシを優先します。
- 平均だけでは長文を判定できないため、**1文字あたりの最悪値**にも上限（既定6.0）を設けています。稀だが必要な読みを切らないよう、実測の上限より少し余裕を持たせた値にしています。
- 評価は1件あたり約12msかかるため、1回の変換で採点するのは**先頭12件まで**です。**それを超えた分は素通りさせずに破棄します**。
- ライブ変換の文は先頭固定で挿入されるためリランクの採点対象外ですが、通常は最良の読みでもあります。候補生成側が出していなかった場合のみ**追加で1回だけ採点**し、この基準値に反映させます。

#### 深掘り探索の結果もゲートを通す

バックグラウンドの深掘り探索（タイプミス補正・候補追加）の結果も、候補ウィンドウに入る前に同じ方針で選別します。

- 採点は**ユーザーが実際に打った読み**に対して行います。各候補が想定する読みで採点すると、キーボード編集の変種は自分の仮説を忠実に変換したものなので高評価になり、選別の役に立ちません。打った読みを共通の尺度にすることで、候補どうしを比較できます。
- マージンの基準は探索の理由で変わります。
  - **候補追加**（候補が少なかった場合）: 既に表示中の候補と競わせる必要があるため、通常パスの最良値も基準に含め、絶対上限も適用します。
  - **タイプミス補正**（入力が壊れている場合）: どの候補も設計上打った読みから外れるため絶対値では全滅します。候補どうしの相対比較のみで、絶対上限は適用しません。
- 件数の上限はありません。良い文が8件見つかれば8件出し、無意味なものしか出なければ0件です。

#### 変換に成功しているときは補正探索を走らせない

タイプミス補正探索を起動する条件のうち、ヒューリスティックな2つ（自動分割による疑い・最上位候補に長い未変換区間）は、正しい入力に対しても誤検知します。そのため**通常パスの最良NLLが0.5以下なら、これらの疑いは無視します**。読みにローマ字が残っている場合はヒューリスティックではなく明確な未完了なので、無条件で探索します。

#### 候補の削除（行の ✕）

候補行の ✕ で、その候補を今後出さないようにできます。

- 抑制は学習キャッシュにセンチネル頻度のエントリとして記録され、**モデル・辞書・学習のどこから来た候補でも除外**します。
- 通常パスだけでなく、**バックグラウンド探索の結果・辞書差し替えで作った候補・ライブ変換の文（先頭固定される文）にも適用**します。ここが抜けていると、削除した候補が1秒後に探索結果として戻ってきたり、先頭固定で復活したりします。
- **削除は文節単位で学習します。** 表面全体の抑制だけでは同じ文を打ち直した時にしか効かず、長文はそもそも学習対象外（`MAX_LEARN_SURFACE_CHARS`）なので何も学べません。削除した候補と残った最上位候補を読みに整列させ、食い違う文節だけを取り出して記録します。文節なら短いので学習でき、以降その読みが出てくる場所すべて（ライブ変換を含む）に効きます。
- 削除した時点で**即座にディスクへ書き込みます**（通常の学習はフォーカス移動まで待ちます）。明示的な指示なので、クラッシュや強制終了でも失われないようにしています。
- 学習ファイルのパスはエンジンが保持します。削除が即書き込みになったため、テストが実ユーザーのキャッシュを壊さないようにするためです。
- なお、これは**GGUFモデル自体の再学習ではありません**。ローカルで再学習する仕組みは持っていないため、更新されるのはIMEの学習モデル（抑制リストと文節の学習）です。

### Learning Cache

ユーザーが選択した変換結果を記憶し、次回以降の変換で優先表示します。

- 保存先: `~/Library/Application Support/com.kashiko.kashiko-im/learning.tsv`
- 完全一致と前方一致（予測変換）の両方に対応
  - 例: 「早稲田大学」を一度変換すると、次回「わせだ」と入力した時点で候補に表示
- ライブ変換で表示していた文は、Space押下時の候補で**必ず1番目**に来ます。候補生成側が同じ文を出した場合も先頭へ引き上げるため、リランクで下位に沈んで見失うことはありません。Space・↓ はその次（2番目）から選択が始まります（1番目は↑で戻れます）
- 学習候補は変換時（Space押下後）に最大3件表示。入力中は候補ウィンドウを出さず、ライブ変換のプリエディットのみを表示します
- スコアはrecency（最終使用日時）重視 + 頻度補正
- IME切り替え・ウィンドウ切り替え時に自動保存（commit のたびには保存しない）
- `[learning] enabled = false` で無効化可能
- 学習履歴を削除するには: `rm ~/Library/"Application Support"/com.kashiko.kashiko-im/learning.tsv`
