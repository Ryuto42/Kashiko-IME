# kashiko-im

macOS Swift フロントエンドから使われる日本語IMEエンジン。入力ステートマシン、ローマ字→ひらがな変換、ニューラルかな漢字変換、学習キャッシュ、辞書引きを提供します。

インストール手順は [kashiko-macos](../kashiko-macos/README.md) を参照してください。

> [!NOTE]
> モデル推論だけでは語彙が限られるため、システム辞書の併用を強く推奨します。同梱されていないため別途インストールが必要です（[Dictionary](#dictionary)）。

## Key Bindings

### ひらがな入力モード

| キー | 動作 |
|------|------|
| 文字キー | ローマ字入力 → ひらがな変換 |
| Space / Tab / ↓ | かな漢字変換を開始 |
| Enter | ひらがなのまま確定 |
| Escape | 入力をキャンセル |
| Backspace | 1文字削除 |
| Delete | カーソル位置の文字を削除 |
| ← → | カーソル移動 |
| Home / End | カーソルを先頭 / 末尾に移動 |
| Ctrl+K | カタカナモードに切り替え |
| Ctrl+Space | 全角スペースを入力 |

### 変換モード

| キー | 動作 |
|------|------|
| Space / Tab / ↓ | 次の候補 |
| ↑ | 前の候補 |
| ← → | 変換対象の文節を単語単位で左右に移動 |
| Shift+← → | 変換対象の文節を単語単位で伸縮 |
| 1-9 | 候補を番号で選択・確定 |
| Enter | 選択中の候補を確定 |
| Escape | 変換をキャンセル（ひらがなに戻る） |
| Ctrl+Backspace | 確定した直後に押すと確定を取り消して変換モードに戻る |
| 文字キー | 選択中の候補を確定して新しい入力を開始 |

候補ウィンドウはマウス操作にも対応します。行にカーソルを乗せると出る ✕ でその候補を削除でき、下部のボタンで推論を追加実行できます。

### モード切り替え

| キー | 動作 |
|------|------|
| Shift+英字 | 英数字モードに切り替え + 大文字入力（Enter / Escape で確定するとひらがなに戻る） |
| Ctrl+K | カタカナモードに切り替え |
| Right Super | 英数字/カタカナ → ひらがなモードに復帰 |
| Ctrl+Shift+L | ライブ変換のON/OFF |

英数字モードでは文字がローマ字変換されず、そのまま入力されます。日本語と英語を混ぜて入力してSpaceを押すと、ひらがな部分のみが変換されます。

### 英単語の自動判定

ひらがなモードのままローマ字で打っても、英単語はそのまま英字で残ります（`kyouhagoogledekensaku` → きょうはgoogleで検索）。判定するのは、ローマ字として読めない語、製品名・固有名詞、ローマ字の読みが日本語の語にならない語（`issue` → いっすえ）、カーソル前が英文のときの普通の英単語です。`make`・`name` のように日本語としても読める語は日本語のままです。サービス名などは通常の表記になります（`github` → GitHub、`iphone` → iPhone、`html` → HTML）。単語表は `kashiko-engine/data/english.tsv` にあります。

- 変換候補には英字にしない読み（すべてかな）も出ます。それを選んで確定すると、次からその語は英字にしません。逆に英字の候補を選んで確定した語は、次から英字になります

`:` で始めると絵文字モードに入り、ショートコードから絵文字を検索できます。

## Configuration

設定ファイル: `~/Library/Application Support/com.kashiko.kashiko-im/config.toml`

全項目の既定値と説明は [`config/default.toml`](config/default.toml) にあります（各行に日本語コメント付き）。主な項目:

| 項目 | 内容 |
|---|---|
| `live_conversion` | ライブ変換の有効化 |
| `composing_chunk_len` | ライブ変換で1回のモデル変換が扱う読みの最大文字数（1キーあたりレイテンシの上限） |
| `strategy` | 変換ストラテジー（下記） |
| `num_candidates` | 変換候補数の目標値 |
| `n_threads` | 推論スレッド数。CPU高負荷時に小さくするとレスポンスが改善します |
| `model` / `light_model` | メイン / 軽量モデル |
| `use_context` / `max_context_length` | 前方文脈の使用と長さ |
| `dict_path` | システム辞書パス |
| `[learning] enabled` / `max_entries` | 学習の有効化とエントリ上限 |

### Conversion Strategy

| 値 | 説明 | 読み込むモデル |
|---|---|---|
| `adaptive` | 既定。レイテンシに応じてメイン・軽量モデルを動的に切り替え | メイン + 軽量 |
| `light` | 軽量モデルのみ。メモリ消費が少なく低スペック機向け | 軽量のみ |
| `main` | メインモデルのみ（ビームサーチなし） | メインのみ |

## Live Conversion

入力と同時に変換結果をプリエディットへ表示します。長文でも1キーあたりのレイテンシを一定に保つため、バッファを内部で `composing_chunk_len` 文字までのチャンクに分割し、編集した箇所のチャンクだけを再変換します。分割は内部的なもので、ユーザーには連続した1つのプリエディットとして見えます。記号・数字の連続は日本語とは別チャンクに分けてそのまま通します。

変換はgreedyデコードですが、greedyは各ステップで最善手に飛びつくため近視眼的で、ビーム探索なら避けられる不自然な文に入り込むことがあります。そこで**自己評価による条件付き再生成**を行います。生成時のlogitsから文字単位NLLを求め（サンプリング直前の値を読むだけなので追加の推論コストはゼロ）、閾値を超えたときだけビーム探索で作り直します。毎キーストロークでビームを回すのは現実的でないため、「悪いと判定したときだけ」払う設計です。

学習キャッシュもライブ変換に反映されますが、モデルを飛ばして即返すことはしません。学習は読みだけをキーに記録するため文脈を持たず、ある文で覚えた形が別の文脈でも出続けてしまうためです。学習形とモデルの出力が食い違ったときだけ両者を文脈込みでスコアリングし、学習側に優遇を与えて選びます。

## Context-aware Conversion

同音語の選択は直前の文に依存するため、カーソル左側の確定済みテキストを変換プロンプトの文脈スロットに渡します。

- 長さは `max_context_length` で決まります。前の一文が収まる長さが必要で、短すぎると判別の手がかりが切り落とされます。長くするとプロンプトが伸びるためレイテンシとのトレードオフです。
- 文脈の取得は macOS の `string(from:)` に依存しますが、Electron系エディタやターミナルなど実装していないアプリが多く、そこでは空で届きます。その場合は**このIME自身が直近に確定したテキスト**で代用します（カーソル左にあるのは同じ文字列なので成立します）。アプリが返せる場合は常にそちらを優先します。
- 代用文脈はフォーカス移動で破棄します。別のアプリ・別の位置では直前の確定内容が文脈として成立しないためです。

## Dictionary

辞書の構築・管理については [kashiko-cli の README](../kashiko-cli/README.md) を参照してください。

- **システム辞書** — double-array trie ベース。既定パスは `~/Library/Application Support/com.kashiko.kashiko-im/dict.bin`（`dict_path` で変更可）。`make install` が自動でダウンロードします。存在しない場合は辞書なしで動作します
- **ユーザー辞書** — `user_dicts/` 配下のファイルをすべて自動読み込み（KRKNバイナリ・Mozc TSV を自動判定）

変換候補の優先順位:

1. 📝 学習キャッシュ
2. 👤 ユーザー辞書
3. 🤖 モデル推論 ＋ 📚 システム辞書（尤度で並べ替え・選別）
4. 🔄 Rewriter（英字全角半角・記号バリアント）
5. ひらがな / カタカナ（常に最下部）

半角カタカナは候補に表示しません。ひらがな・カタカナ行は長くなると中略表示にして、他の行の幅を圧迫しないようにしています。

## Candidate Quality

モデルと辞書の候補は、確定前に言語モデルで文字単位の尤度（NLL）を評価して**並べ替えと選別**を行います。ビーム順はデコーダ自身の経路確率にすぎず、同音の紛れを上位に残してしまうためです。

- 表示する候補数は**固定ではなく質で決まります**。最良候補から一定のマージンを超えて劣る候補は、順位を下げるのではなく除外します。マージンは相対値で、文の難易度に自動追従します。逆にすべてが高評価なら全件残します
- 絶対上限も併用し、最良候補すら悪い場合に「最良に近いから」で通ることを防ぎます
- 平均だけでは長文を判定できないため、**1文字あたりの最悪値**にも上限を設けています。長文で1文字だけが誤変換でも平均はほとんど動かないため、局所的な破損は局所的な指標でしか見えません
- 評価にはコストがかかるため採点数に上限があり、**それを超えた分は素通りさせずに破棄します**。採点していない候補はゲートを通せないため、通していた頃は稀な読みがそのまま候補ウィンドウに並んでいました。破棄の例外は学習候補のみ
- ライブ変換の文は先頭固定で挿入されるためリランクの対象外ですが、通常は最良の読みでもあります。候補生成側が出していなかった場合のみ追加で採点し、基準値に反映させます

### 短い読みは削らない

4文字以下の読みでは、ゲートは並べ替えるだけで削除しません。1語だけの読みではモデルに判定材料の文がなく、低スコアは「珍しい」であって「間違い」ではないためです。人名の漢字違いは、この扱いをしないと辞書にもモデルにも存在するのに全部消えてしまいます。長文は従来通り厳格に絞ります（そこでは実際の文に対して採点されているので、文中で不自然な同音語は本当に間違いです）。

このとき、2つのかなが混ざった純かな候補（モデルが途中で変換を諦めたもの）と、括弧・装飾記号を含む辞書エントリ（ニックネームや注記）は除外します。

### 数字の扱い

読みに無いASCIIは捏造として除外しますが、**数字だけは別扱い**です。かなの数詞は正当に数字になるため、同じ扱いにすると数を含む文の変換が全滅します。数字は**位置**で判定し、助数詞（または続く数字）が後ろに来ていれば正当、それ以外の場所に現れた数字は捏造とみなします。

数詞と助数詞に分解できる読みは、数字を使った表記も候補に出します（辞書は読み全体をキーにするため該当する項目がなく、モデルのビームも digit 形を安定して出さないため、この経路がないと候補に載りません）。読みがきれいに分解できたときだけ動くので、助数詞でない語が数詞の後ろに来ても発火しません。

### 外来語の英語表記

借用語は辞書もモデルも日本語表記しか返さないため、英語表記は表から引く以外に到達できません。カタカナ読み→英語の表を持っています（`kashiko-engine/data/loanwords.tsv`）。

収録範囲はエンジニアリング・ビジネス系の用語に限っています。カタカナのまま自然に読める日常語は意図的に入れていません。読み全体が表と一致した時だけ動くため、文中の一語だけを英語にしたい場合は矢印キーの文節移動でその語を対象にしてください。

表に一致した読みは1語の借用語だと確定するので、そこでは半端に変換されたかな候補を除外し、カタカナ形を先頭に繰り上げます。この形自体は一般には正当なので（カタカナ＋ひらがな活用）、表が1語として認識した読みに限って適用します。

## Deep Search

品質ゲートは存在する候補を並べ替えるだけなので、正解が生成されていなければ何もできません。そこでバックグラウンドで探索を続け、見つかった候補を後から追加します。

- **別スレッドで走ります。** メインループは常に1本のチャネルで待機しており、モデル呼び出しの中に入りません。推論中も候補の移動・確定・削除がそのまま効きます。以前は「リクエストが来ていない時だけ1ステップ進める」インターリーブ方式でしたが、実行中のタスクが終わるまでキーイベントが待たされ、体感は「固まる」になっていました
- 変換器は `Arc` で共有します。推論は `&self` で呼び出しごとに自前のllama.cppコンテキストを作るためロックは不要です
- ジョブは自己完結型（読み・文脈・タスク列・変換器ハンドル・採点の基準値）で、ワーカーはエンジンの状態に触りません
- 変換が変わった（確定・再入力・区切り変更）時はキャンセルフラグを立て、誰も見ない結果のためにCPUを使い続けないようにします。結果が戻った時点で読みとスコープを照合し、古いものは捨てます
- 探索結果も通常パスと同じ方針で選別します。編集した読みに対するビームなので、日本語として成立していても意味を成さない文が出るためです。採点は**ユーザーが実際に打った読み**に対して行います（各候補が想定する読みで採点すると、キーボード編集の変種は自分の仮説を忠実に変換したものなので高評価になり、選別の役に立ちません）
- マージンの基準は探索の理由で変わります。候補追加なら既に表示中の候補と競わせ、タイプミス補正なら候補どうしの相対比較のみにします（後者はどの候補も設計上打った読みから外れるため、絶対値では全滅します）

### 推論ボタン

候補ウィンドウ下部の補助行がボタンになっています。押すたびにビーム幅と結果上限を引き上げるため、同じ探索の繰り返しになりません。変換候補が少ないときは押さなくても自動で探索します。

### スペースキーは細いビームで返す

ビーム幅がそのままコストです。広いビームは長文で数秒かかる一方、貪欲パスは長さに関係なくごくわずかで済みます。この広いビームがスペース押下の待ち時間そのものでした。

そこで同期パスは細く保ち、幅はワーカーに移しました。短い読みは同音異義がスペースの主目的なので少しだけ広げ、長い読みは貪欲1本にします（これはライブ変換が既に表示していた文でもあります）。

**同期パスが設定値より少ない候補しか要求しなかった場合は、必ず背景探索を予約します。** これが対になっていないと、辞書が充実した読みは「候補が少ない」と判定されないので探索が走らず、モデルのビームだけが見つけていた候補が丸ごと失われます。背景側のゲートも、4文字以下の読みでは並べ替えるだけにします。

トレードオフとして、広いビームだけが見つけていた候補のうち背景の探索でも出ないものは失われます。

### タイプミスの補正

変換に失敗したと判断したときだけ、キーボード配置を考慮した打鍵誤り（隣接キー・転置・母音抜け・ローマ字残り）を推定して候補を探します。

補正探索を起動する条件のうちヒューリスティックなもの（自動分割による疑い・最上位候補に長い未変換区間）は正しい入力に対しても誤検知します。長いかな連続を正当に含む文は「変換失敗」と判定されがちで、その変種は自分の読みには忠実なので、補正結果をいくら採点しても弾けません。そのため**通常パスの最良NLLが十分低ければ、これらの疑いは無視します**。読みにローマ字が残っている場合はヒューリスティックではなく明確な未完了なので、無条件で探索します。

絵文字モードではこの経路を通しません。ショートコードは `:` の後にASCIIが続く形なので、ローマ字残りの分割が必ず発火してしまいます。

## Learning Cache

ユーザーが選択した変換結果を記憶し、次回以降の変換で優先表示します。完全一致と前方一致（予測変換）の両方に対応し、スコアは最終使用日時を重視して頻度で補正します。

- 保存先: `~/Library/Application Support/com.kashiko.kashiko-im/learning.tsv`
- **保存時は暗号化します**（ChaCha20-Poly1305）。入力内容の記録なので、バックアップ・同期クライアント・インデクサがホームディレクトリを走査した時に平文で拾われる状態にしておくべきではありません。鍵はインストール時に生成し、キャッシュの隣に `0600` で置きます
  - **買えるものと買えないもの**: 鍵が同じディレクトリにあるので、ユーザー権限で動いているものは両方読めます。守れるのは「通り掛かりに読まれること」で、アカウントを取られた相手からは守れません。鍵をログインキーチェーンに置けばそこは上がりますが、Swift側から起動時に鍵を渡す仕組みが必要になります
  - 認証付きなので、壊れたり改変されたファイルは黙って化けずにエラーになります
  - 暗号化前の平文キャッシュはそのまま読み込み、次回保存時に暗号化して書き直します
- 外来語表・助数詞表は**種**であって、順位は学習が決めます。一度確定すればその選択が学習キャッシュに入り、次回から上位に出ます。複数語の英語も学習対象です
- ライブ変換で表示していた文は、Space押下時の候補で**必ず1番目**に来ます。候補生成側が同じ文を出した場合も先頭へ引き上げるため、リランクで下位に沈んで見失うことはありません。Space・↓ はその次から選択が始まります（1番目は↑で戻れます）
- 学習候補は変換時に最大3件表示。入力中は候補ウィンドウを出さず、ライブ変換のプリエディットのみを表示します
- 誤変換やスペルミスに由来する意味の取れない学習は自動的に除外し、極端に長い文章は学習・候補表示の対象外です
- IME切り替え・ウィンドウ切り替え時に自動保存（確定のたびには保存しません）
- `[learning] enabled = false` で無効化できます

### 候補の削除（行の ✕）

候補行の ✕ で、その候補を今後出さないようにできます。

- 抑制は学習キャッシュにセンチネル頻度のエントリとして記録され、モデル・辞書・学習のどこから来た候補でも除外します
- 通常パスだけでなく、バックグラウンド探索の結果・辞書差し替えで作った候補・ライブ変換の文（先頭固定される文）にも適用します。ここが抜けていると、削除した候補が探索結果として戻ってきたり先頭固定で復活したりします
- **削除は文節単位で学習します。** 表面全体の抑制だけでは同じ文を打ち直した時にしか効かず、長文はそもそも学習対象外なので何も学べません。削除した候補と残った最上位候補を読みに整列させ、食い違う文節だけを取り出して記録します。文節なら短いので学習でき、以降その読みが出てくる場所すべて（ライブ変換を含む）に効きます
- 削除した時点で即座にディスクへ書き込みます（通常の学習はフォーカス移動まで待ちます）。明示的な指示なので、クラッシュや強制終了でも失われないようにしています
- これは**GGUFモデル自体の再学習ではありません**。更新されるのはIMEの学習モデル（抑制リストと文節の学習）です
